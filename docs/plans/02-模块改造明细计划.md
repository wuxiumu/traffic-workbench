## 2. lib/stats.ts 混合查询设计

```
windowStart = dateStr(today - (RETENTION_DAYS-1))
siteIdOf(key) → SQLite sites（低频，直接查）

summary(siteKey):
  today / yesterday：窗口内 → pipeline HGETALL tw:stats
                   窗口外 → daily_stats 单行
  total = SQLite SUM(daily_stats WHERE date < windowStart)
        + Redis 窗口各日 pv/uv/ip 求和

dailySeries(siteKey, days):
  for 每个日期 d in (today-days, today]:
    d >= windowStart → Redis HGETALL（pipeline 批量，缺键补零）
    else → SQLite daily_stats
  输出连续序列（含补零）

details(siteKey, days, limit):
  pages = SQLite page_daily GROUP BY path (date < windowStart)
        + Redis 各窗口日 ZREVRANGE pages WITHSCORES
  refs 同理（direct → 「直接访问」展示）
  JS 合并排序取 Top

feed(siteKey): LRANGE tw:feed 0 19 → [{t,p,r,d}]
```

API `/api/stats` 响应增加：`feed`、`windowDays`（RETENTION_DAYS）。

## 3. seed.mjs 双路径写入

- 站点：demo0001（我的博客）/ demo0002（产品官网），沿用 v1 键
- 对每天 d：
  - `d >= windowStart` → 直接写 Redis：RPUSH events（JSON 同线上格式）、SADD+计数、ZINCRBY、EXPIRE；feed 灌 20 条
  - `d < windowStart` → SQLite：批量 INSERT events → `recomputeDay()`（与 flush 同一函数，保证口径一致）
- 结束打印两侧统计，便于断言

## 4. docker-compose 设计

```yaml
services:
  redis:
    image: redis:7-alpine
    command: ["redis-server","--appendonly","yes","--maxmemory","512mb","--maxmemory-policy","allkeys-lru"]
    volumes: [redis-data:/data]
    healthcheck: redis-cli ping
  app:
    build: .
    environment: REDIS_URL=redis://redis:6379, RETENTION_DAYS, FLUSH_CRON,
                 CRON_SECRET, ARCHIVE_DAYS, ADMIN_PASSWORD, IP_SALT
    volumes: [./data:/app/data]
    depends_on: {redis: {condition: service_healthy}}
    ports: ["127.0.0.1:3000:3000"]
volumes: {redis-data:}
```

Redis 不映射宿主端口（仅容器网络内可达）。

## 5. 回归不变量（改完必须逐条过）

1. m.js 埋码不变，采集行为对网站透明
2. 同访客同日多次 PV：pv 累加、uv=1；换 IP 换访客：uv/ip 各 +1
3. 未登录访问 `/api/stats|/sites` → 401；登录正常
4. 排行、趋势、total 在窗口边界无重复计数（重点回归 30/90 天视图拼接处）
5. flush 前后 daily_stats 与 Redis 当日计数一致
