# 01 · 需求与目标分析

> 状态：已确认 ｜ 关联：`docs/plans/01-架构升级总体执行计划.md`

## 1. 背景需求（v1，已交付）

自托管网站流量统计工作台，统计页面 **IP / PV / UV**，含历史趋势。技术约束：嵌入 JS 采集、Node.js 全栈、4 核 8GiB 单机、Docker 部署、服务器与服务健康监控。

v1 已实现：采集脚本 m.js、指标大盘、7/30/90 天趋势、页面/来源排行、站点管理与接入代码生成、密码登录、健康探针与 webhook 监控、Docker 单容器。

## 2. 新需求（v2，本次升级）

用户明确要求：

| # | 需求 | 说明 |
|---|---|---|
| R1 | 引入 Redis | Next.js + SQLite + **Redis** 三件套 |
| R2 | Redis 存近期数据 | Redis 存 **7 天**内容数据，且**天数可配置** |
| R3 | SQLite 做历史日志 | SQLite 主要承担历史日志归档职责 |
| R4 | 每日定时归档 | 每天定时任务把 Redis 数据存入 SQLite |
| R5 | 充分利用 Redis 特性 | 不能只是「把 SQLite 换成 Redis」，要用对数据结构 |
| R6 | Docker 部署 | app + redis 容器化编排 |
| R7 | 保持 4 核 8GiB 预算 | 内存占用需给出评估 |

## 3. 衍生设计目标

- **热路径零 SQLite**：采集写入只碰 Redis（内存级延迟），SQLite 仅归档与配置读
- **读路径实时性**：大盘「今日/昨日/趋势/排行」全部来自 Redis，无磁盘聚合查询
- **归档幂等**：定时任务可重跑、可补跑，重复执行不产生重复计数
- **可运维**：保留天数、cron 表达式、事件上限等全部环境变量化；Redis AOF 持久化

## 4. 非目标（本期不做）

- 国家/地区归属（ip2region）：字段与数据链路已预留，库未接
- 多用户/角色权限：仍是单管理员密码
- 原始事件明细页（按天查询 events 归档）：数据已入库，UI 后续补
